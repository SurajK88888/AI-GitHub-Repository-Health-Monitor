# Quality Rules

Favor correctness, readability, accessibility, reliability, and maintainability over cleverness. Make failure states explicit. Keep behavior deterministic when practical.

Respect formatting, linting, type checking, and repository conventions. Treat warnings as work to assess, not noise to ignore. Do not reduce test coverage or disable checks merely to make a pipeline pass.

Measure performance before optimizing. Add observability for important workflows: structured events, meaningful errors, and stable correlation identifiers where supported. Define a rollback or recovery path for risky changes.
