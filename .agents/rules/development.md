# Development Rules

Understand the affected code and contract before editing. Make the smallest change that solves the stated problem. Preserve established conventions unless a deliberate migration is approved.

Use clear names and simple control flow. Keep functions and modules focused. Remove dead code only when it is in scope and verified unused. Avoid speculative abstractions and unrelated refactors.

Validate all untrusted input at boundaries. Make errors actionable and safe. Add or update documentation whenever behavior, setup, configuration, or a public interface changes.

Do not silently change user-visible behavior or data semantics.
