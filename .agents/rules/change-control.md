# Change Control

Start with the requested outcome and acceptance criteria. State assumptions that materially affect scope. Inspect the current repository state before changing files.

Keep commits or change sets cohesive. Do not overwrite user work, reformat unrelated files, or make destructive changes without explicit approval. Update migrations, contracts, feature flags, and release notes when applicable.

Before handing off, review the diff for scope, regressions, generated files, sensitive data, and missing tests. Report what changed, what was verified, and what remains unverified.
