# Architecture Decisions

Record durable, consequential choices in `docs/decisions/` using `templates/adr.md`.

Create an ADR when a decision changes a public contract, data model, security posture, dependency direction, deployment model, or has costly reversal.

ADRs are immutable history: supersede rather than rewrite. Keep the decision, context, alternatives, consequences, owner, and review date concise. Do not create ADRs for routine implementation details.

Use an experiment or spike when evidence is insufficient; record its outcome if it drives a decision.
