# Intake Workflow

1. Read the user request, repository instructions, and relevant `docs/` pages.
2. Inspect the current state: project structure, dependencies, related code, tests, and working changes.
3. Define outcome, scope, constraints, risks, and acceptance checks.
4. Ask only questions that block a safe, material decision; otherwise record assumptions.
5. Create or update `docs/tasks/` for work that spans sessions or has meaningful complexity.

Never treat project documentation as a substitute for inspecting the actual code and configuration.
